# Past competition practice

Reviewed October 7, 2026 against the local **2027** event rules. The catalog contains ten complete archived papers, 669 answer fields, and eight event subjects. The Scioly archive index contains 909 Division B/C source listings; source entries without a converted rubric stay visible in each event's archive list. Coverage is deliberately explicit: most events and all Division A events still have no verified papers. A competition is labeled Regionals, States, or Nationals only when that tier is reported; an invitational without one is labeled “Level not reported.”

## Subject alignment and source limitations

Subject rotation matching is not a claim that every historical question complies with every 2027 subtopic or level restriction. The expanded alignment/scoring note on each paper states the differences before the student starts. Original historical questions remain intact.

- Anatomy 2023 covers the 2027 respiratory/digestive/immune rotation. The more recent nervous/endocrine/sensory rotation was not substituted.
- Heredity papers cover the same genetics subject area but do not exhaust the expanded 2027 population-genetics syllabus. Some questions are now restricted to States/Nationals. BullSO also includes one gel-electrophoresis question beyond the 2027 techniques list.
- Disease Detectives retains the same three subject areas. BullSO's bias/confounding/herd-immunity items cover current States/Nationals material. MCQ 8 asks a specific disease-category association outside the current rules; the student note identifies that exception.
- Freshwater Dynamic Planet and the Greenbrier Water Quality paper match the 2027 freshwater subjects; oceanography and glacier-rotation papers were not included. Everyday-weather/climate Meteorology papers remain excluded because 2027 uses severe storms.
- UT Austin follows its published key, including a disputed incomplete-dominance answer in question 25. Berkeley's key is headed BBSO but matches its paper; source terminology in questions 18 and 28 is retained. Columbia's written answers 11–13 are matched to the corresponding questions by content; key weights take precedence where they differ from paper weights, and written question 40 uses the paper's weight because its key does not state one. Multi-select question 24 requires both correct choices.
- National test packs offered for purchase were not acquired. No invented questions or competition provenance fill gaps in the library.

## Grading and persistence

After submitting, students can use **Auto Grade** on the saved result. It rechecks nonblank written responses against the existing rubric, preserves MCQ keys and original student text, and updates that attempt's score and percentage. Successful reviews are saved once; repeated requests reuse the saved result. Failures leave the earlier score intact and allow retry. Instructor reviews take precedence. Auto Grade does not create an attempt or grant more progress, points, or assignment credit.

Converted papers without a published answer key may declare `gradingMode: 'ai-generated'`, `keyUrl: null`, and an empty `keys` object. Every question must include its complete `prompt`, choices, and any necessary diagram/table context in `context`; catalog validation rejects bare question-number placeholders. Auto Grade first asks Gemini for independent reference solutions without student answers, then grades the saved answers against those generated criteria. The server validates question IDs, option IDs, criterion weights, score bounds, and completeness. Generated reference answers and estimated scores are labeled as AI-generated; unresolved source context remains pending for instructor review. This supports converted question content, not source-only archive links whose questions have not yet been extracted.

Authenticated server grading ignores client scores. MCQ keys, numerical tolerances, accepted short-answer variants and rubric criteria stay in the server catalog; initial paper responses omit them. Submitted results include corrections: correct MCQ choices are green, written rubric answers are red, and exact student input remains visible. When `GEMINI_API_KEY` is configured, unresolved written criteria are sent without account identifiers to Gemini 3.5 Flash by default (`GEMINI_MODEL` can override it) with a strict JSON rubric response; the server validates every returned question, criterion, and point bound before applying it. Provider failures keep the answer pending for instructor review rather than assigning a guessed score.

MCQ sets require all correct choices. Numerical answers support decimal/scientific notation, fractions, stated units and published tolerance ranges. Equivalent notation not recognized by the parser goes to review. Recognized short answers grade automatically; unmatched nonempty prose is sent to Gemini when configured, rather than receiving a fabricated semantic grade. Blank fields score zero. Instructors review any response the model marks uncertain against the linked full rubric and enter bounded partial credit. Scores and percentages are provisional until that review is complete.

Submission UUIDs are scoped to the authenticated user and paper, making retries idempotent. Each distinct practice paper contributes once to practice progress; the first attempt can complete one pending Practice assignment in that event, while repeat submissions remain available for feedback without additional assignment credit or ranked points. Exact answers and reviewed scores are persisted in `practice_submissions`; `test_attempts` remains the dashboard record. Drafts are saved only in that student's browser under user/division/test-specific keys. Previous-attempt review preserves an unsubmitted draft.

## Extending and verifying

Edit `scripts/build-practice-catalog.mjs`, then run `node scripts/build-practice-catalog.mjs`. Verify the actual competition date, level, division, complete test, every answer-key marking, weights, all diagrams and 2027 subject rotation before adding a paper. Do not infer a year from an upload date. Explicitly record disagreements and practice-specific weighting. Keep test IDs stable because they identify saved submissions.

Run `npm test`, `npm run typecheck`, and `npm run build`. Catalog validation checks question IDs, correct choices, criterion totals and overall totals. Persistence tests cover cross-school review restrictions, forged score rejection, duplicate submissions, preserved text and assignment completion. `node --experimental-strip-types scripts/practice-browser-check.mjs` checks the real UI with isolated mocked accounts; it expects port 3002 unless `TEST_BASE_URL` is set. It creates no real accounts or student records. Screenshots are stored in ignored `documents/qa/`.
